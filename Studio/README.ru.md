# KAIC Studio

Новый нативный клиент на Rust и egui/eframe (Glow/OpenGL), с поддержкой Linux Wayland/X11. Чёрный интерфейс, локальные разговоры, потоковый чат llama.cpp, анализ текстовых вложений, клиент контрольного API KAIC и лаборатория ComfyUI. Код приложения написан заново в этом репозитории.

## Сборка и запуск

Нужен Rust 1.95 или новее и доступные системные библиотеки оконного окружения. На этой машине сборка проверяется Rust 1.99.1. Все зависимости — опубликованные пакеты crates.io; подмен и локальных замен библиотек нет. `Cargo.lock` хранится в репозитории. Параллелизм Cargo ограничен двумя заданиями в `.cargo/config.toml`.

```bash
cargo fmt --check
cargo test --locked
cargo build --locked
./target/debug/kaic-studio
```

Если домашний кэш Cargo доступен только для чтения, задайте отдельный кэш внутри проекта перед командами Cargo:

```bash
export CARGO_HOME="$PWD/.cargo-home"
cargo test --locked
cargo build --locked
```

Приложение запускают из графического сеанса. Исполнитель принимает только одну операцию за раз; отклонённый submit не сбрасывает отмену. Закрытие прекращает приём заданий, отменяет ожидание и отбрасывает ещё не начатую работу. Оно не требует Electron, браузера или облачного AI. Для изолированной проверки данных доступен параметр `--data-dir /абсолютный/путь`. Для QA также поддерживаются `KAIC_STUDIO_DATA_DIR=/абсолютный/каталог` (приоритет над XDG) и `KAIC_STUDIO_WINDOW_TITLE="KAIC Studio — Проверка"`. Явный относительный путь/путь к файлу отклоняется без перехода к пользовательской истории. Обычный каталог данных — `$XDG_DATA_HOME/kaic-studio`, либо `~/.local/share/kaic-studio`.

## Диалог и файлы

Слева находятся новый разговор и поиск по заголовкам и сообщениям. На узком окне история открывается кнопкой меню. Enter отправляет сообщение, Shift+Enter добавляет строку. Ctrl+1/2/3 переключают вкладки, Ctrl+, открывает настройки, Ctrl+N создаёт разговор после завершения активной операции, Ctrl+L фокусирует поле сообщения. Ошибка показана возле ответа; в прямом режиме можно повторить последний запрос без дублирования сообщения пользователя. Частичный ответ сохраняется как предыдущая попытка. «Стоп» останавливает собственный запрос; загруженный сервер остаётся доступен. «Выгрузить» завершает и дожидается только собственного дочернего сервера. При выходе приложение также останавливает свой сервер.

Модель выбирается над полем ввода или на вкладке «Модели». По умолчанию выбирается проверенная gemma26, затем glm30. Недоступные и медленные модели видимы отдельно. Каталог показывает точный размер, путь, SHA из манифеста, сохранённую скорость, признак порога 10 ток/с и отдельный результат сохранённого теста чата. Хеш не выдаётся за тест чата или скорости. Статус `verified…`, существующий GGUF с совпадающими именем и размером обязательны для загрузки; приложение доверяет результату проверки манифеста и не перечитывает многогигабайтный файл для повторного SHA при каждом запуске.

«Файл» открывает поле пути. Поддерживаются UTF-8 файлы txt, md, rs, py, c/cpp/h/hpp, json, toml, yaml/yml, js/ts/tsx/jsx, css, html, sh, xml, csv, log. Лимит — 128 КиБ на файл и 384 КиБ вместе. Бинарные, неподдерживаемые и слишком большие файлы отклоняются. До отправки вложение можно убрать. В запрос включаются имя и весь текст с номерами строк. Содержимое сохраняется в разговоре; исходный файл не меняется. Пути Documents и каталоги учётных данных запрещены, в том числе через symlink.

Бюджет учитывает историю, вложения и ответ. Перед загрузкой используется консервативная оценка по байтам UTF-8; она может отклонить текст, который фактически поместился бы. Перед генерацией выполняются `/apply-template` и `/tokenize` установленного llama.cpp. Превышение лимита отклоняет запрос без обрезки. Можно начать новый разговор, убрать вложения или явно изменить контекст. Для контекста выше живого профиля требуется согласие в настройках текущего сеанса. Достижение лимита ответа и оборванный поток помечаются явно.

Markdown отображается локальным небольшим renderer: заголовки, абзацы, списки, выделение, inline-код и fenced code с выделением и копированием. Полный CommonMark, таблицы Markdown и подсветка синтаксиса пока не реализованы.

## llama.cpp

Используется установленный `/home/kirpich/.llama.cpp/build/bin/llama-server`. Библиотеки задаются только дочернему процессу: `LD_LIBRARY_PATH=<bindir>:/opt/cuda/lib64`; окружение сервера очищается от унаследованных токенов и конфигурации. Приложение не подключается к чужому серверу и не останавливает его. Порт выбирается свободный, адрес — `127.0.0.1`. Перед передачей истории проверяются inode LISTEN-сокета в `/proc/net/tcp` и его fd в `/proc/<собственный child>/fd`, живой child, аутентифицированный каталог и случайный alias экземпляра. Ключ экземпляра хранится в собственном временном файле 0600 и памяти, не передаётся в argv и удаляется после завершения собственного сервера. Чужой `/health 200` сам по себе не подтверждает готовность. Повторное использование сервера требует того же канонического GGUF, SHA/размера, inode/dev, времён изменения файла и фактического контекста.

Перед загрузкой проверяются `nvidia-smi`, отсутствие сторонних GPU compute-процессов и параметры `llama-server --help`. При занятом или недоступном GPU приложение показывает причину, не освобождает GPU самостоятельно. Проверенный профиль читается при каждом запуске модели из `/home/kirpich/models/context-tuning/profiles.json` по точному repo. Неизвестная модель получает явно неизмеренный резервный профиль 4096 токенов. Каталоги читаются из пяти путей `BUILD_BRIEF.md` и дополнительно из разрешённого родителем `/home/kirpich/models/ibm-selection/progress.json`. Granite Switch 4.1 30B помечена экспериментальной плотной моделью; загрузка GGUF не активирует специализированные aLoRA/guardian/decision адаптеры. Pending/preallocated файлы не считаются готовыми.

Используются `--fit on`, `-c`, `-b 512`, `-ub 128`, `-fa on`, `-fitt 768`, параметры KV и потоков профиля. Число GPU-слоёв остаётся незаданным. Из экспертных флагов разрешены только `-ncmoe`/`--n-cpu-moe` и `-ot`/`--override-tensor` с картой CPU. Загрузка имеет таймаут 180 с и проверку `/health`; готовность не считается успешным ответом. Поток использует `/v1/chat/completions` и SSE с сохранением дроблёного UTF-8, обработкой ошибок и `[DONE]`. Пустой текстовый ответ считается ошибкой.

Реальный короткий smoke использует тот же `ManagedServer::chat` → `stream_chat`, что и GUI, а не отдельный CLI-транспорт:

```bash
./target/debug/kaic-studio --list-models
./target/debug/kaic-studio --smoke-chat gemma26 --report verification/smoke-chat.json
```

Smoke нужно запускать после освобождения GPU. Он ограничивает ответ 64 токенами, ждёт непустой реальный текст и сохраняет результат либо реальную ошибку. Полный срок — до 180 с загрузки и до 180 с запроса. При завершении его собственный сервер выгружается. Автоматические тесты не загружают GGUF и не занимают GPU.

## KAIC

В настройках выберите контрольный API KAIC, по умолчанию `http://127.0.0.1:4545`. Токен берётся из `KAIC_CONTROL_TOKEN` или вводится в маскированном поле; он хранится только в памяти, не входит в настройки или экспорт истории и скрывается при показе ответа проверки API. Работают `GET /status`, `/backend`, `/models`, `/local-models`, `POST /tasks` с `{text, allow_manual:false}`, опрос `GET /tasks/{id}` и запрос отмены `POST /tasks/{id}/cancel`.

Отображается настоящий транскрипт задачи. `done`, `failed`, `cancelled` различаются; `paused`, `waiting_for_human` и ожидающее подтверждение инструмента показываются как ожидание. Продолжение и выдача разрешений инструментам не реализованы: контракт тела `/continue` не был предоставлен. «Обновить задачу» сохраняет ранние сообщения и повторно проверяет последнюю задачу. После запроса отмены статус запрашивается повторно; пока backend не подтвердил `cancelled`, отмена не считается завершённой. Задачу можно обновить после перезапуска клиента. Отмена ожидания POST создания задачи не означает, что backend её не принял: при отсутствии ID клиент явно сообщает неопределённый исход и предлагает проверить KAIC до повтора. Для смены прямого режима на KAIC или обратно нужен новый разговор.

Это клиент существующего API, а не встроенный планировщик KAIC. Исходники, процессы, база и конфигурация старого KAIC не меняются. При недоступности API или отсутствии авторизации остаётся прямой режим.

## Медиа и ComfyUI

Адрес по умолчанию — `http://127.0.0.1:8188`. «Проверить ComfyUI» обращается к `/system_stats` и `/object_info`. Нужен запущенный пользователем backend с установленными моделями и API workflow JSON — объектом ID → `{class_type, inputs}`, не визуальным графом редактора. Файл workflow можно прочитать по пути (до 4 МиБ) или вставить в редактор.

Для замены положительного промпта укажите точный ID нужного текстового узла. Меняется только его `inputs.text`. Пустой ID оставляет все тексты workflow как есть. Установленные идентификаторы моделей можно получить из `object_info` и применить к явно указанному узлу/входу; соответствие class_type проверяется. Перед генерацией выгрузите собственную чат-модель.

Клиент отправляет `/prompt`, наблюдает `/history/{prompt_id}`, уточняет выполнение по `/queue`, проверяет ошибки исполнения и скачивает изображения/видео через URL-кодированные параметры `/view`. Имена на диске генерирует сам клиент; обход путей запрещён. Успех показывается после успешного статуса backend и проверки скачанных файлов: PNG/JPEG полностью декодируются с ограничением памяти/размеров, остальные разрешённые форматы проверяются установленным `ffprobe` без shell с таймаутом. Временный файл остаётся `.part` до подтверждения и затем атомарно переименовывается. При ошибке или отмене `.part` не считается результатом. Если `ffprobe` отсутствует, соответствующее медиа не объявляется подтверждённым. Есть лимиты 32 артефакта, 512 МиБ на файл, 1 ГиБ вместе и час наблюдения. «Остановить текущую операцию» завершает наблюдение или загрузку; задание ComfyUI на backend продолжает работу. Глобальный `/interrupt` не вызывается. При отмене создания до получения prompt_id исход отправки помечается как неизвестный: проверьте очередь перед повтором, чтобы не создать дубликат.

В `outputs` сохраняются workflow, промпт, найденные seed, время начала, длительность, состояние/ошибка и пути полученных файлов. Записи доступны после перезапуска. PNG/JPEG имеют встроенный предпросмотр с ограничением размера декодирования. Другие поддержанные контейнеры изображений/видео открываются локально через `xdg-open` с массивом аргументов, без shell; встроенного проигрывателя видео и предпросмотра WebP/GIF/AVIF пока нет. Проверка контейнера/видеопотока через `ffprobe` не является полным декодированием всех кадров видео.

`ffprobe` уже доступен на проверенной машине; установщик его не устанавливает. Если backend отсутствует, клиент сообщает ошибку подключения и предлагает запустить его/проверить адрес. Приложение не устанавливает Python-backend, не скачивает checkpoints и не создаёт демонстрационное медиа вместо результата сервера. Локальные тестовые серверы в тестах явно помечены и не считаются реальной генерацией.

## Сохранение и установка

История и настройки записываются атомарно через уникальный временный файл, fsync и rename. Файлы данных создаются с правами 0600. Размер JSON ограничен 32 МиБ; при превышении старый файл сохраняется. Повреждённый `state.json` не перезаписывается: клиент использует отдельный `state-recovery-*.json` и при следующем запуске ищет последнюю исправную резервную историю. Незавершённый ответ после перезапуска помечается как неподтверждённый. Два одновременно работающих экземпляра с одним каталогом данных не поддерживают слияние истории: используйте отдельные `--data-dir`.

Необязательная установка выполняется пользователем после проверки сборки:

```bash
./target/debug/kaic-studio --install-local
```

Команда копирует текущую сборку в `~/.local/bin/kaic-studio` и создаёт `~/.local/share/applications/kaic-studio.desktop` с русским описанием и app_id/window title `KAIC Studio`. Она не требует sudo, не меняет системные каталоги, не создаёт значок на рабочем столе и отказывается перезаписывать существующие одноимённые файлы. В рамках этой задачи установщик не запускался: запись ограничена новым репозиторием.

Итоговые команды и границы проверки находятся в `BUILD_REPORT.ru.md` и `verification.json`. Прохождение HTTP-контрактов и headless egui не заменяет реальную проверку NVIDIA, окна Wayland/X11, KAIC с авторизацией и ComfyUI с workflow на этой машине.
