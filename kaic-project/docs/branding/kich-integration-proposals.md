## KAIC: утверждённое минимальное изменение

Основание: `kaic-ui/src/App.tsx:13` описывает существующий layout;
`components/Header.tsx:56` содержит бренд и форму создания задачи;
`components/Workspace.tsx:44` — пустую рабочую область с подсказкой;
`App.css:13` — трёхколоночную сетку.

Утверждённое место — **только пустая рабочая область**. Исходный PNG отображается
около 192×192 с короткой подсказкой о создании/выборе задачи. При выборе задачи
изображение исчезает, история и форма продолжения остаются прежними. Второй
экран, router, onboarding, runtime-зависимости и сетевые запросы не добавлены.

Файлы внедрения после подтверждения:

- Новый `kaic-project/kaic-ui/src/assets/kich/Kich.png` — побайтовая копия канона.
- Новый `kaic-project/kaic-ui/src/components/Kich.tsx` — небольшой reusable img
  с размером, alt и сохранением пропорций; без backend-логики и анимаций.
- Новый `kaic-project/kaic-ui/src/components/Kich.css` — локальные классы картинки
  и пустого состояния; без глобальной смены цветов/сетки.
- Изменение только пустой ветки `kaic-project/kaic-ui/src/components/Workspace.tsx`.
- `kaic-project/kaic-ui/src/App.css`: на ширине до 760 px существующие панели
  располагаются в одну колонку, форма переносится; панели не скрываются.

Импорт PNG через Vite должен дать production asset URL, совместимый с уже
заданным `base: './'` в `vite.config.ts`. После build проверить существование
выходного PNG, ссылку из JS и совпадение байтов. Не менять Electron main.

Альтернатива по выбору владельца — также небольшой Кич в header. Она потребует
отдельной правки `Header.tsx` и проверки высоты/ширины формы. Из-за полей в
каноническом PNG маленькое изображение менее разборчиво; первая рекомендация
не затрагивает header.

Сохранить `Header`, `TaskList`, `Workspace`, `DetailsPanel`, `StatusBar`, polling,
Task API и всю существующую обработку ошибок. В `api/controlCenter.ts` и
`StatusBar.tsx` уже есть незакоммиченные изменения — их не трогать. Backend,
P0 tool-approval и P1 lifecycle находятся вне scope.

## Приёмка после разрешения

1. SHA-256 обеих исходных копий неизменен; копия приложения совпадает с каноном.
2. Нет crop, искажений, CSS recolor, новых выражений или анимации.
3. Проверить пустое и рабочее состояние, light/dark usage и узкую/широкую область.
   Существующая grid KAIC имеет фиксированные 260/320 px колонки: нельзя объявлять
   всё приложение адаптивным только по размеру изображения.
4. Проверить alt/decorative mode, отсутствие фокуса и дублирующего live announcement.
5. Vite build + TypeScript; проверить production URL PNG и Electron `file://`.
   Тестового npm script у активного KAIC UI нет. Не выдавать его отсутствие за pass.
6. Для MIND — отдельные согласованные build/test проверки после разрешения;
   нынешний read-only осмотр не подтверждает успешную сборку MIND.
7. Скриншот листа ассета не подменяет скриншот реальной интеграции. После правок
   отдельно проверить создание/выбор задачи и сохранение существующего поведения.
