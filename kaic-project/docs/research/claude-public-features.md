# Claude Code: публичные концепции и границы применения в KAIC

Дата проверки: **18 октября 2026, UTC**. Область: официальная документация,
публичные README и LICENSE. Это исследование документированных интерфейсов,
а не проверка внутренней реализации Claude Code или его runtime.

## Решение

Использовать Claude Code как публичный источник требований к взаимодействию:
возобновляемая беседа, видимые вызовы инструментов, отдельное решение человека,
ограниченная делегация и явные состояния прерывания. Реализация KAIC должна
оставаться собственной и обращаться к существующему KAIC HTTP API. Подключать
Claude CLI или Agent SDK ради первого терминального интерфейса не требуется.

## Матрица публичных возможностей

Обозначения: **концепция** — самостоятельно реализуемое поведение;
**интерфейс** — документированный способ взаимодействия с продуктом;
ни один пункт не означает права на его собственническую реализацию.

| Возможность и первичный источник | Что документировано | Применение в KAIC |
|---|---|---|
| [Обзор](https://code.claude.com/docs/en/overview) — концепция | Работа с кодом, командами, MCP и несколькими интерфейсами поверх агентного движка | Терминальный клиент поверх KAIC, без второго оркестратора |
| [Skills](https://code.claude.com/docs/en/skills) — формат и расширения | `SKILL.md`, метаданные, загрузка тела при использовании, ручной вызов; базовый Agent Skills и расширения Claude различаются | Сначала каталог и происхождение; активация только после собственного backend-контракта |
| [Subagents](https://code.claude.com/docs/en/sub-agents) — концепция и конфигурация | Отдельный контекст, инструменты, модель, ограничения, `maxTurns`, возможная worktree-изоляция | Будущие дочерние задачи с `parent_id`, бюджетом, владельцем файлов и отменой |
| [Permissions](https://code.claude.com/docs/en/permissions) — политика и интерфейс | Правила deny/ask/allow, режимы Manual/Plan и другие; проверяет приложение, а не модель | Policy должна жить в backend. Для первого этапа — только существующий точный `request_id` |
| [Project memory](https://code.claude.com/docs/en/memory) — концепция | Инструкции проекта, пользовательские заметки и область правил; инструкции являются контекстом, а не принудительной политикой | Сохранять `AGENTS.md`; не превращать найденный Markdown в разрешение инструмента |
| [Context window](https://code.claude.com/docs/en/context-window) — концепция | Расходы инструкций, файлов и описаний инструментов; отдельный контекст подзадач; структурированное сжатие | Показывать неизвестное usage явно; позднее добавить измеряемый бюджет и сводки с происхождением |
| [Checkpointing](https://code.claude.com/docs/en/checkpointing) — концепция | Снимки прямых файловых изменений и перемотка беседы; shell-эффекты не являются полным объектом восстановления | В первом этапе не обещать откат. Позднее отделить снимок файлов от статуса внешнего действия |
| [Workflows/worktrees](https://code.claude.com/docs/en/common-workflows#run-parallel-sessions-with-worktrees) — концепция | Отдельные checkout/ветки для параллельных сессий и планирование перед правками | Отдельный checkout уменьшает конфликты, но не заменяет ограничения процесса и файловой системы |
| [Interactive mode](https://code.claude.com/docs/en/interactive-mode) — интерфейс и концепция | Клавиатурное управление, команды, история ввода, прерывание и фоновые команды | Собственные краткие команды KAIC, различение закрытия клиента и отмены задачи |
| [Sessions](https://code.claude.com/docs/en/sessions) — интерфейс и концепция | Сохранение беседы, выбор и возобновление; незавершённый инструмент не должен считаться автоматически повторённым | Переоткрывать существующую задачу по UUID; неопределённый внешний эффект требует разбора |
| [Programmatic use](https://code.claude.com/docs/en/headless) — интерфейс | `-p`, JSON/NDJSON `stream-json`, частичные события; `parent_tool_use_id` связывает сообщения подагентов | Образец требований к будущему event API KAIC, без зависимости от CLI Claude |
| [Plugins](https://code.claude.com/docs/en/plugins) — интерфейс и концепция | Пакет метаданных, навыков, агентов, hooks и MCP; namespace предотвращает столкновения имён | Отложить исполняемые plugins; сначала read-only метаданные и проверяемая схема |

Режимы автоматического разрешения и обхода prompts Claude Code здесь описаны
только как существующие публичные возможности. Перенос таких режимов в KAIC не
предлагается: они не нужны минимальному этапу и изменили бы границу полномочий.

## Привязка к текущему KAIC

Проверены актуальные файлы активного дерева, включая незакоммиченное P0-исправление:

- `kaic-backend/src/control_center_api.rs`: маршруты `/tasks`, `/tasks/:id`,
  `/continue`, `/pause`, `/cancel`, `/tool-decision`, `/models`, `/status`.
- `kaic-backend/src/task_store.rs`: `Task`, `ContextEntry`, статусы,
  `ToolApproval`, `ToolServerIdentity` и отдельная таблица разрешений SQLite.
- `docs/tool-approval-contract.md`: точный снимок цели, атомарное решение,
  одноразовое исполнение и ограничение группы вызовов.

Уже можно строить собственный клиент для списка задач, истории, создания и
продолжения задачи, статуса моделей, отмены и подтверждения. «Сессия» первого
этапа — представление существующей задачи, а не новый тип в backend.

Проверенная таблица HTTP-маршрутов не содержит streaming/SSE, списка подагентов,
активации навыков, файлового preview/diff, usage/cost или выбора произвольного
backend. Поэтому интерфейс должен показывать соответствующие возможности как
недоступные, а не изображать работающую интеграцию. Обновление истории поллингом
не является токенным streaming. Сохранённая история не доказывает восстановление
незавершённого исполнения после аварии backend.

## Требования к карточке подтверждения

Это собственные требования KAIC, основанные на его P0-контракте:

1. Сохранить снимок `pending_tool_approval` из ответа backend. Показать UUID
   задачи и запроса, `execution_id`, сервер (`command`, `args`, `peer_name`),
   инструмент и точные `arguments`; прокрутка должна позволять прочитать всё.
2. Подтверждать именно показанный снимок. Изменение выбора задачи или смена
   `request_id` закрывает старую карточку, не подставляя новую цель под нажатие.
3. Передать `POST /tasks/:id/tool-decision` с исходными `request_id` и `approve`.
   Не выбирать запрос по последней записи истории или `tool_call_id` модели.
4. На конфликте, отмене и сетевой неопределённости обновить задачу; не повторять
   решение автоматически и не сообщать об успешном исполнении до ответа.
5. Управляющие последовательности терминала из аргументов показывать безопасным
   видимым представлением. Не исполнять их как terminal escape codes; исходные
   байты сохраняются в снимке backend и не редактируются интерфейсом.

## Статическая оценка доверия расширениям

Применены `kirpich-research` и `kirpich-skill-audit`. Оценка:
**0 — блокировано, 1 — требуется отдельный аудит, 2 — допустимо в данной области**.

| Объект | Права | Исполнение | Данные/секреты | Итог |
|---|---:|---:|---:|---|
| Чтение официальных документов и LICENSE | 2 | 2 — не исполняются | 2 — репозиторий не отправляется | PASS: исследование |
| Собственная реализация общих взаимодействий | 2 — без заимствованного кода | 2 — стандартные проверки KAIC | 2 — локальный API | PASS: минимальный клиент |
| Импорт неизвестного skill/plugin | 1 — лицензия каждого файла | 1 — scripts/hooks требуют аудита | 1 — endpoints и credentials неизвестны | CONDITIONAL: не импортировался |
| Копирование реализации CLI или обход разрешений | 0 | 0 | 0 | REJECT |

Это статическая проверка происхождения и границ, не runtime-аудит Claude Code.
Сторонние skills, scripts, hooks, MCP-процессы и install-команды не запускались.
Исполняемый plugin не продвигался в KAIC; тестовый fixture и runtime-проверка
такого plugin неприменимы к выполненному исследованию и должны предшествовать
его будущему включению.

## Следующая проверка

Для терминального клиента нужны локальные HTTP-дубли: доступная/недоступная
связь, 401, пустая история, смена задачи во время approval, stale/duplicate 409,
отмена, длинные Unicode-аргументы и враждебные escape sequences. После этого —
ручной PTY-прогон на Artix с настоящим backend. Функции Claude Code в данном
исследовании не запускались; источники подтверждают документацию, а не
совместимость установленного CLI с конкретной версией KAIC.
