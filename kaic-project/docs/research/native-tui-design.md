# KAIC: решение о нативном терминальном интерфейсе

Дата исследования: 18 октября 2026 года. Статус: проект решения и критерии приёмки; перечисленные возможности не считаются реализованными без проверки кода клиента. Область — активный `kaic-project`, без переноса вложенного дерева разработки.

## Контекст и проверенные границы

KAIC уже владеет маршрутизацией, Scheduler, LM Studio, MCP и SQLite. Интерфейс должен быть клиентом этого ядра, а не вторым оркестратором. Старый `experiments/kaic-terminal` — отдельный GGUF/llama.cpp REPL с собственной историей в памяти (`src/main.rs:1`, `src/repl.rs:25`, `Cargo.toml:17`). Его нельзя выдавать за клиент существующего HTTP API.

В `kaic-backend/src/control_center_api.rs:162` зарегистрированы `/tasks`, `/tasks/:id`, `continue`, `pause`, `cancel`, `tool-decision`, `/models`, изменение temperature и `/status`. SSE/WebSocket, проекты, дочерние агенты, skills, файловые операции и затраты провайдера в этом API отсутствуют. `Task` и снимок `ToolApproval` описаны в `task_store.rs:91`. P0-контракт изложен в [tool-approval-contract.md](../tool-approval-contract.md).

P1 частично исправлен: регистрация исполнителя, continue/decision/cancel используют общую блокировку; pause отправляет сигнал остановки и ранний continue получает конфликт. Однако Video по-прежнему вызывается перед cancel-select (`control_center_api.rs:1419`); crash recovery исполнителя не реализован. История SQLite переживает процесс, работающий inference — нет. Интерфейс не должен автоматически продолжать найденную после перезапуска задачу.

## Выбор и альтернативы

Выбран самостоятельный Rust HTTP-клиент с оригинальным reducer состояния и терминальным renderer. После согласования зависимостей предпочтительны Ratatui + Crossterm. HTTP DTO отделены от виджетов: будущий desktop-клиент использует тот же KAIC API, а не терминальные типы.

| Вариант | Обоснование |
| --- | --- |
| Rust + Ratatui/Crossterm, собственные взаимодействия | Предпочтительно: один язык с ядром, без Electron, тестирование буфера, независимое развитие UI |
| Отдельно лицензированные OpenTUI-компоненты | Не включать в первый этап: публичный интерфейс TypeScript поверх Zig, дополнительные Bun/toolchain и FFI при Rust-клиенте |
| Клиент OpenCode HTTP API | Возможная отдельная интеграция; сейчас добавляет второй backend с собственными сессиями и разрешениями, не решает подключение UI к KAIC |
| Rust + непосредственные терминальные escape-последовательности | Допустимо для временного ограниченного прототипа, но переносимость, Unicode, layout и восстановление терминала становятся обязанностью KAIC |

OpenTUI описывает TypeScript API, React/Solid adapters и Zig-ядро; это не Rust-библиотека. [Официальный README OpenTUI](https://github.com/anomalyco/opentui). OpenCode публикует OpenAPI и SSE: полезно перенять разделение клиента и сервера, но его маршруты `/session` и `/event` нельзя вызывать у KAIC. [Документация сервера OpenCode](https://opencode.ai/docs/server/).

Откат обратим: отдельный клиент не меняет БД, Router, Scheduler или MCP; удаление клиента не затрагивает ядро. Переработка backend ради TUI в этап не входит.

## Зависимости и происхождение

Проверенные опубликованные версии: Ratatui **0.30.2**, Crossterm **0.29.0**. Предлагаемые, ещё не добавленные зависимости:

```toml
ratatui = { version = "=0.30.2", default-features = false, features = ["crossterm_0_29"] }
crossterm = { version = "=0.29.0", default-features = false, features = ["events", "bracketed-paste"] }
```

Ratatui требует Rust 1.88/edition 2024, опубликованный Crossterm — Rust 1.63/edition 2021. Рабочая ветка `master` Crossterm уже отличается: MSRV следует проверять по registry-артефакту. Эти ограничения совместимы с проверенным в сессии Rust 1.99, но новый minimum toolchain проекта нужно зафиксировать отдельно. [Manifest Ratatui](https://docs.rs/crate/ratatui/0.30.2/source/Cargo.toml), [Manifest Crossterm](https://docs.rs/crate/crossterm/0.29.0/source/Cargo.toml.orig).

Обе библиотеки — MIT; при распространении сохраняются соответствующие copyright и license notices. [Лицензия Ratatui](https://docs.rs/crate/ratatui/0.30.2/source/LICENSE), [лицензия Crossterm](https://github.com/crossterm-rs/crossterm/blob/master/LICENSE). Это использование библиотечных API (категория B), без копирования кода OpenCode или Claude Code. Лицензии всего разрешённого Cargo-графа проверяются после выбора конкретного lockfile; MIT верхнего пакета не заменяет такую проверку.

Набор отключает календарь, макросы UI, цвета подчёркивания, OSC52 clipboard, дополнительные backend и async EventStream. В активном backend уже есть reqwest/Tokio/Serde, но нет Ratatui/Crossterm. Новый бинарник внутри backend может разделить HTTP-зависимости, однако Cargo всё равно собирает прямые зависимости пакета. Отдельный crate изолирует TUI от llama.cpp/native dependencies, ценой отдельного lockfile. Число дополнительных разрешённых crates, время сборки, RAM и размер binary пока **не измерены**. Существенные зависимости не вводятся без согласования.

## Модель клиента

Единственный владелец состояния UI — event loop: `Input`, `Resize`, `PollFinished`, `CommandFinished`, `Quit`. Сеть выполняется отдельно и присылает типизированный результат с generation выбранной сессии; запоздалый ответ другой сессии не заменяет активную.

Состояние включает список задач, выбранный ID, последнюю подтверждённую сервером задачу, draft input, scroll, connection state и отдельный замороженный approval snapshot. Сетевой модуль не содержит renderer; renderer не исполняет shell, MCP или файловые операции. Не добавлять небезопасный «локальный обход» HTTP-разрешений.

HTTP по умолчанию ограничен `http://127.0.0.1:4545`, Bearer берётся из `KAIC_CONTROL_TOKEN`, не из аргументов процесса. Запрет перенаправлений и proxy, ограничения времени и размера ответа, отсутствие токена в ошибках. Другие адреса требуют отдельного согласованного контракта; интерфейс не передаёт токен произвольному URL.

Polling: выбранная задача примерно раз в секунду, список/status реже, без перекрывающихся запросов. При ошибке GET — ограниченная задержка повторения с верхним пределом; 401 блокирует действия до исправления конфигурации. Данные остаются видимыми с пометкой времени и «нет связи». POST автоматически не повторять: при утрате ответа результат неизвестен; сначала получить актуальное состояние.

## Поддержка существующих возможностей

| Возможность | Контракт и поведение первого этапа |
| --- | --- |
| Новая беседа | `POST /tasks {text}`; это задача, не независимый session resource |
| Повторное открытие | `GET /tasks`, затем `/tasks/:id`; история SQLite, без обещания восстановления процесса |
| Следующая реплика | `/continue {message}` после завершения/паузы при отсутствии approval; cancelled не возобновлять |
| Ввод во время работы | Не выдавать за streaming-input; backend имеет ограниченное число followup-проходов, но не delivery acknowledgement/очередь |
| История и инструменты | Отображать `context.role/content/at/tool_call_id`; неизвестные роли безопасно показывать текстом |
| Разрешение | Только `pending_tool_approval` и `/tool-decision`; история не источник полномочий |
| Модели | `/models`: реестр/loaded/context capacity; не представлять capacity как использованные tokens |
| Статус | `/status`: memory budget, busy models, active operation, число генераций; это не полный healthcheck LM Studio |
| Выбор модели | API создания принимает category/allow_manual, но не model ID; выбор конкретной модели помечать недоступным |
| Streaming | Нет server stream; показывать ожидание/новые сохранённые записи, без искусственных token deltas |
| Подагенты/skills/workspaces/diff | Нет контрактов; разделы «не поддерживается API», без вымышленных endpoint и фонового сканирования диска |
| Costs/tokens | «Не предоставляется backend», без подсчёта по длине текста |

## Подтверждение без смены цели

Открытие панели захватывает **весь** снимок: task/execution/request/tool-call ID, имя инструмента, исходную строку arguments, server command/args/peer. Смена выбранной задачи закрывает панель или оставляет её явно привязанной к исходной задаче; обработчик решения никогда не читает текущий selected ID вместо захваченного.

Показать аргументы полностью в прокручиваемой области; не ограничиваться красивым JSON: он скрывает дублирующиеся ключи и преобразует escape-последовательности. Исходное UTF-8 представление сохраняется неизменным в памяти; управляющие символы, bidi и невидимые символы показываются видимыми escapes с явной пометкой. Предусмотреть горизонтальную прокрутку/перенос; если лимит/ошибка не позволяют проверить полный снимок, одобрение отключено. Новая версия снимка сбрасывает просмотр.

Перед отправкой выполнить свежий GET исходной задачи, сравнить весь снимок и `waiting_for_human`. При несовпадении закрыть возможность одобрения; не подставлять новый ID. Затем отправить только захваченный `request_id` и явный `approve`. Эта предварительная сверка улучшает UX, но окончательную атомарную проверку делает backend. Гонка после GET безопасно заканчивается 409.

Решение одноразовое; клавиша Enter по умолчанию не одобряет. Рекомендуется отдельная команда просмотра, явное действие подтверждения и доступный отказ. Отключить повтор клавиш и paste как источник решений; `Event::Paste` только меняет draft. Отказ не равен отмене задачи: сервер пишет результат отказа и может продолжить диалог. Выход TUI не отменяет backend автоматически. После начатого внешнего эффекта гарантированного отката нет.

## Оригинальный интерфейс и Кич

Монохром, без Electron/web runtime и зависимости от Wayland API. На широком экране: список задач слева, история в центре, раскрываемая activity/approval справа; снизу draft/status. При ширине менее 100 колонок правая панель заменяет центральную; менее 72 — одно содержимое и переключаемый список. Очень маленький размер показывает краткую справку и не позволяет подтверждать скрытую цель. Фактические пороги проверяются на 40×12, 80×24 и 140×40.

`Tab` меняет фокус, стрелки выбирают/прокручивают, `PageUp/PageDown` читают историю, `Ctrl+N` создаёт draft, `F1` открывает помощь, `Esc` закрывает панель, `Ctrl+C` завершает клиент. Для команды «отмена задачи» нужно отдельное обозначенное действие. Символы `y/n/q` внутри draft являются обычным текстом. Пустой или пробельный ввод не отправляется. Не полагаться на расширенные сочетания, не поддерживаемые обычным терминалом.

Оригинальный Кич отображается только в welcome/пустой сессии/помощи:

```text
  +-----+
--| >_  |--
  +-----+
   [] []
```

Это маленький телевизор с короткими прямыми руками и прямоугольными ногами, без антенны, лица и пальцев. Для монохромного режима фон экрана можно дать серым, рамку чёрным, `>_` белым; ASCII fallback сохраняет форму. Не анимировать mascot вместо настоящей телеметрии.

## Терминальные границы и проверка

Непроверенный текст никогда не записывается напрямую как ANSI: ESC/OSC/CSI, CR, BEL и C0/C1 нейтрализуются на границе renderer. Markdown не исполняет HTML, команды, ссылки или embedded terminal sequences. Code fences показываются как текст; полноценный syntax highlighting откладывается до отдельной лицензированной библиотеки. UTF-8 не резать byte offsets; курсор/Backspace учитывать grapheme boundaries, ширину CJK/combining и перенос. ASCII fallback обязателен для рамок.

RAII guard восстанавливает raw mode, cursor, bracketed paste и alternate screen при нормальном выходе и ошибке; panic hook восстанавливает терминал до вывода traceback. SIGINT/SIGTERM обрабатываются кооперативно, suspend/resume требуют отдельной проверки. SIGKILL/power loss не позволяют обещать cleanup. Не вызывать `stty`, fish/bash и shell для терминального управления.

| Риск | Детерминированная проверка |
| --- | --- |
| Запуск/выход/ошибка/panic | PTY: состояние termios и cursor/alternate cleanup; без внешних моделей |
| Недоступный backend и reconnect | Локальный HTTP double, timeout/401/404/500, отсутствие повторов POST и утечки Bearer |
| Восстановление истории | Снова открыть тот же task ID; interrupted Running не запускается автоматически |
| Approval identity | Другая задача/новый request ID/изменённый аргумент/server; ни одного POST по неподтверждённому снимку |
| Stale/duplicate/cancel | Fresh GET плюс 409; двойное нажатие отправляет один POST; cancel-before-approval не восстанавливает запрос |
| Terminal injection/Unicode | ESC/OSC52/CR/bidi/CJK/combining/emoji; длинные аргументы доступны полностью либо approve запрещён |
| Resize | Буферные снимки на минимальном/среднем/широком экране, без underflow/panic и скрытого confirm |
| Неподдерживаемые возможности | Нет вызовов `/agents`, `/skills`, `/event`, `/files`; нет фиктивной стоимости и подагентов |
| Файловая граница | Клиент не читает workspace и не запускает команды; только разрешённый HTTP destination |

Сначала модель состояния и HTTP-контракты, затем renderer/PTY и ручная проверка на Artix/fish/доступном терминале. Буферные тесты не подтверждают поведение конкретного Wayland-эмулятора. При последующем добавлении SSE нужны идентификатор/порядок события, cursor reconnect, replay и cancellation; простой перенос OpenCode endpoint без этого недопустим.
