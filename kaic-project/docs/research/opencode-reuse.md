# OpenCode: исследование и матрица повторного использования

Дата проверки: 2026-10-18. Решение: KAIC сохраняет собственное Rust-ядро и создаёт независимый терминальный клиент к существующему API. Код, ресурсы и зависимости OpenCode в этом этапе не импортируются. Лицензии и ревизии перечислены в [provenance-opencode.md](provenance-opencode.md).

## Проверенная архитектура

В проверенной ревизии OpenCode пакет `packages/tui` имеет версию **2.0.32**, помечен `private: true` и зависит от OpenTUI Core/Keymap/Solid, SolidJS и внутренних workspace-пакетов. Это TypeScript/Solid TUI поверх нативного движка, а не Rust-библиотека. [Закреплённый manifest](https://github.com/anomalyco/opencode/blob/214fb7fdbab9ad13773629839f1178382400cf97/packages/tui/package.json).

OpenTUI предоставляет Zig-движок, TypeScript bindings и React/Solid renderers, flexbox, ввод и прокрутку. Официальный README описывает дополнительные графические возможности, которые не нужны минимальному KAIC. Подключение OpenTUI создало бы дополнительный JS/Zig toolchain. [Закреплённый README](https://github.com/anomalyco/opentui/blob/f8f608e2b9a41685d613a1156708ff06c826c3ce/README.md).

Два наиболее полезных паттерна: отделённый HTTP-клиент интерфейса и структурированные части сообщений/события активности. OpenCode документирует сервер с OpenAPI 3.1 и SSE; это полезный ориентир для будущего KAIC event API. Наличие документации не доказывает межверсионную стабильность схем. [Server](https://opencode.ai/docs/server/).

## Матрица решений

**A** — код доступен для прямого использования по проверенной лицензии; **B** — доступен публичный API/интерфейс, стабильность проверяется отдельно; **C** — собственная реализация в Rust; **D** — не подходит текущему этапу. A означает юридическую возможность, а не рекомендацию копировать.

| Компонент / идея | Класс | Применение к KAIC и основание |
|---|---|---|
| OpenTUI Core, Solid, Keymap | A/B → D для первого этапа | Корневая MIT и MIT manifest Core проверены; TS-интерфейс не соответствует цели Rust-native. Все транзитивные лицензии не проверены. [OpenTUI](https://github.com/anomalyco/opentui/tree/f8f608e2b9a41685d613a1156708ff06c826c3ce) |
| Внутренние компоненты OpenCode TUI | A → C | Root MIT разрешает reuse при соблюдении условий; private workspace и связанные пакеты делают извлечение дорогим. Отдельный аудит конкретных файлов обязателен перед переносом. [Manifest](https://github.com/anomalyco/opencode/blob/214fb7fdbab9ad13773629839f1178382400cf97/packages/tui/package.json) |
| OpenCode как внешний сервис | B → D для первого этапа | Документированы HTTP/OpenAPI/SSE. Добавит второй оркестратор, модель сессий и полномочия поверх KAIC. Возможный будущий изолированный адаптер требует закрепления версии и contract-тестов. [API](https://opencode.ai/docs/server/) |
| Сессии и дочерние задачи | C | Отображать явную связь родитель/потомок и состояние. Источник описывает primary/subagents, отдельные child sessions и навигацию. Реальное делегирование требует backend-контракта KAIC. [Agents](https://opencode.ai/docs/agents/) |
| Диалог, инструмент и поток | C | Разделять text/reasoning/tool, показывать `running/completed/error`; хранить идентичность частей. Проверенный renderer содержит Markdown, tool states и retry UI. Состояния KAIC нельзя выдумывать. [Session renderer](https://github.com/anomalyco/opencode/blob/214fb7fdbab9ad13773629839f1178382400cf97/packages/tui/src/routes/session/index.tsx) |
| Разрешения и интерактивное решение | C | Полезны `allow/ask/deny` и отдельный запрос разрешения. OpenCode предлагает once/always/reject; KAIC на первом этапе сохраняет только точное одноразовое решение с `request_id`. Перенос permissive defaults, auto mode и pattern-wide approvals не рекомендован. [Permissions](https://opencode.ai/docs/permissions/) |
| Модели / провайдеры | C | Показывать реальную доступность и выбор модели отдельно от интерфейса. OpenCode документирует AI SDK/Models.dev, provider/model ID и variants; перенос TS provider stack дублировал бы `ModelBackend` KAIC. [Models](https://opencode.ai/docs/models/) |
| Diff, patch preview, подсветка | C | Проверенный renderer использует PatchDiff, Markdown syntax styles. В KAIC начать с безопасного текстового preview; редактирование требует workspace API, а подсветка — отдельной оценки Rust-библиотеки и её лицензий. [Renderer](https://github.com/anomalyco/opencode/blob/214fb7fdbab9ad13773629839f1178382400cf97/packages/tui/src/routes/session/index.tsx) |
| Клавиатура, контекст, восстановление | C | Полезны переключение сессий, `/compact`, `/details`, список команд. Документированный undo/redo также меняет файлы через Git: KAIC не должен выдавать просмотр истории за откат файлов. [TUI](https://opencode.ai/docs/tui/) |
| Plugin hooks и skills | C/D | События жизненного цикла полезны. Автозагрузка проектного JS/TS и автоматическая установка npm-плагинов не подходят границе доверия KAIC. Нужны явное доверие, источник и ограниченные полномочия. [Plugins](https://opencode.ai/docs/plugins/) |
| LSP | B/C, позже | Использовать сам протокол, при необходимости. OpenCode документирует diagnostics feedback и затраты серверов; автоустановка не нужна. Сначала существующие CLI-проверки проекта. [LSP](https://opencode.ai/docs/lsp/) |

## Безопасность и восстановление

Интерфейс подтверждения должен отображать точный сервер, инструмент, аргументы, задачу и идентификатор запроса; решение отправляется только к этому снимку. Просмотренные OpenCode материалы не заменяют независимую проверку P0-инварианта KAIC. Retry допустим для чтения состояния; автоматический повтор неопределённого результата инструмента создаёт риск повторного внешнего эффекта.

Серверные session events, части сообщений и отдельный поток активности — хороший последующий контракт, но первоначальный клиент может честно использовать ограниченный polling существующего API. SSE-события OpenCode не являются SSE-контрактом KAIC. При отсутствии данных о токенах, стоимости, субагентах или streaming интерфейс должен прямо показывать недоступность.

## Границы проверки и следующий шаг

Исследование read-only: официальные документация, лицензии, manifests и один renderer; приложение OpenCode не запускалось. Это не полный аудит исходников, безопасности, API-совместимости и транзитивных лицензий. Ни install-скрипты, ни сторонние навыки не выполнялись. Следующий шаг перед любым reuse — выбрать точный файл/пакет и версию, проверить его зависимости/уведомления и зафиксировать обязательства в third-party notices.
