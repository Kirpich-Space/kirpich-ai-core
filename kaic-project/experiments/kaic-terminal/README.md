# KAIC Terminal v0.2

Локальный AI CLI: открывает проект, понимает его структуру, позволяет
общаться с моделью в контексте проекта. Inference-движок — прямое
продолжение `experiments/llama_cpp_smoke`, логика генерации не менялась.

## Сборка (Windows)

Из твоей уже пройденной диагностики `llama_cpp_smoke` известно, что нужно
собирать через генератор Ninja, а не Visual Studio/MSBuild (у последнего
баг с флагом `-j16` в крейте `cmake`). Открой **Developer Command Prompt
for VS 2022** и выполни:

```cmd
cd kaic-terminal
set CMAKE_GENERATOR=Ninja
set LIBCLANG_PATH=C:\Program Files\LLVM\bin
copy kaic.toml.example kaic.toml
```

Поправь `model_path` в `kaic.toml` под свою модель, затем:

```cmd
cargo run -- .
```

Для CUDA:

```cmd
cargo run --features cuda -- .
```

## Использование

```
kaic .                  — открыть текущую директорию как проект
kaic /путь/к/проекту    — открыть проект по указанному пути
kaic --help             — справка
kaic --version          — версия
```

Внутри REPL: `/help`, `/clear`, `/model`, `/temp N`, `/history`, `/read F`,
`/ls [D]`, `/write F`, `/create-file F`, `/create-directory D`, `/git-status`,
`/git-diff`, `/git-log`, `/git-show REV`, `project`, `/exit`.

### Безопасная ручная запись

Команда `/write <относительный путь>` изменяет только существующий файл и
переводит REPL в многострочный ввод. Отдельная строка `/end` завершает ввод,
`/cancel` отменяет его. KAIC показывает unified diff, затем обязательно
запрашивает подтверждение и только после ответа `y`/`yes` начинает запись.

Запись ограничена корнем проекта и выполняется через временный файл с
`flush`/`fsync` и атомарной заменой. Для существующего файла рядом создаётся
неперезаписываемая резервная копия `<имя>.bak.<timestamp-pid>`. После замены
файл перечитывается и сверяется с ожидаемым содержимым, а REPL возвращает отчёт
с путём, количеством записанных байт, результатом проверки, backup и audit log.
Показанный diff подтверждённой операции сохраняется в `.kaic/write-audit.log`.

## Известные ограничения write_file

- Перед записью KAIC повторно проверяет путь и исходное содержимое из preview,
  но не удерживает системную блокировку. Изменение другим процессом между этой
  проверкой и `rename` всё ещё может быть перезаписано.
- Timestamped backups и `.kaic/write-audit.log` накапливаются без ротации,
  ограничения размера и автоматической очистки.
- Если перечитывание и сверка после успешного `rename` завершаются ошибкой,
  автоматический rollback не выполняется. Для существующего файла остаётся
  backup; восстановление пока выполняется вручную.
- Инструмент работает только с UTF-8 текстом. Строки, состоящие ровно из
  `/end` или `/cancel`, зарезервированы протоколом многострочного ввода.
- Preview хранит исходное содержимое, новое содержимое и diff в памяти, поэтому
  изменение очень больших файлов потребует дополнительной памяти.

### Безопасное создание файлов и директорий

`/create-file F` работает только для отсутствующего файла с уже существующей
родительской директорией. KAIC показывает diff `/dev/null → F`, запрашивает
подтверждение и создаёт полностью синхронизированный файл без возможности
перезаписать цель, появившуюся после preview. После создания содержимое
перечитывается и проверяется.

`/create-directory D` создаёт только одну отсутствующую директорию. Родитель
должен существовать: рекурсивное создание намеренно не поддерживается. Перед
`create_dir` показывается preview и запрашивается подтверждение, после операции
тип и расположение директории проверяются.

Backup для этих операций не требуется, потому что существующая цель всегда
считается ошибкой. Обе операции записывают подтверждённый preview в
`.kaic/write-audit.log` до изменения файловой системы.

#### Известные ограничения create_file/create_directory

- Atomic no-clobber для файла использует hard link временного файла и требует
  файловую систему с поддержкой hard links.
- Если удаление временного имени после успешного hard link завершится ошибкой,
  целевой файл останется корректным, но рядом может остаться скрытый temp-файл.
- `create_file` поддерживает только UTF-8 текст и тот же протокол `/end` и
  `/cancel`, что и `write_file`.
- `create_directory` не создаёт отсутствующих родителей и не выполняет
  рекурсивных операций.

### Read-only Git-инструменты

- `/git-status` показывает branch и краткое состояние working tree.
- `/git-diff` показывает tracked-изменения отдельно для unstaged и staged.
- `/git-log` показывает последние 20 коммитов.
- `/git-show REV` безопасно резолвит `REV` в commit OID и показывает commit
  вместе с patch.

Git запускается напрямую без shell. Pager, optional locks, fsmonitor, external
diff и textconv отключены. Вывод ограничен открытым `project_root`, даже если
он является вложенной директорией большего репозитория. На этом этапе нет
`git add`, `git commit`, `git push`, `git reset` и других Git-операций записи.

#### Известные ограничения read-only Git-инструментов

- `/git-diff` показывает только tracked-файлы; untracked-файлы видны в
  `/git-status`, но их содержимое в diff не включается.
- `/git-diff` и `/git-show` целиком собирают вывод в памяти без pagination и
  ограничения размера. Очень большой diff или commit может потребовать много
  памяти.
- `/git-log` использует фиксированный лимит в 20 коммитов.

## Что сознательно НЕ реализовано в v0.2

Planner/Coder/Reviewer, rename/delete, recursive/mass operations, выполнение
произвольных shell-команд, автоматическое изменение файлов моделью,
Git-операции записи, память между сессиями, EmbedIDE, MCP, автономный вызов
инструментов моделью (все инструменты вызываются только вручную пользователем
через команды REPL).
