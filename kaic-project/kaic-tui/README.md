# KAIC CLI

CLI — приоритетный пользовательский интерфейс KAIC. `kaic-cli` — нативный
Rust-клиент существующего Control Center HTTP API; Electron для него не нужен.
Историческое имя каталога `kaic-tui` сохранено. Новые зависимости не добавлены.

## Сборка и запуск

Из этого каталога:

```bash
cargo build --locked --bin kaic-cli
cargo run --locked --bin kaic-cli -- --help
cargo run --locked --bin kaic-cli -- --status
cargo run --locked --bin kaic-cli
```

Кроме `--help`, требуется `KAIC_CONTROL_TOKEN` длиной минимум 16 символов —
тот же токен, который настроен у отдельно запущенного backend. Передавайте его
через окружение, не через argv или сообщения чата. По умолчанию API находится
на `http://127.0.0.1:4545`; `KAIC_API_BASE` или `--backend URL` меняют адрес
только на loopback HTTP. Конфигурация backend/LM Studio остаётся существующей.
CLI сам не запускает сервер, не загружает модели и не меняет настройки системы.

Настройка llama.cpp и выбор модели: [headless llama-server](../docs/llama-server.md).
Флаг `--backend URL` по-прежнему задаёт адрес API KAIC; адрес inference-сервера
задаётся через `KAIC_INFERENCE_URL` при запуске backend.
Диагностика inference: `/backend` или `--backend-info`; реестр моделей: `--models`.

Одноразовые действия: `--tasks`, `--show UUID`, `--send "Текст задачи"`.
`--send` создаёт задачу и возвращает её идентификатор; окончания генерации
не ожидает. Код выхода: `0` — успех, `1` — ошибка API/конфигурации/ввода-вывода,
`2` — неверные аргументы. Не повторяйте POST автоматически после сетевой ошибки:
его результат может быть неизвестен. Сначала проверьте `/tasks` и `/history`.

## Работа в терминале

Введите текст, чтобы создать задачу. Начальный ввод всегда начинает новую
беседу; существующая задача выбирается явно через `/use UUID`.

| Команда | Действие |
| --- | --- |
| `/new`, `/tasks`, `/use UUID` | Новая беседа, список задач, выбор сохранённой задачи |
| `/history` | Полная история выбранной задачи |
| `/status`, `/models`, `/refresh` | Scheduler, загруженные модели, восстановление связи |
| `/pause`, `/cancel` | Пауза или отмена выбранной задачи через backend |
| `/tool`, `/more`, `/close` | Открыть точный запрос инструмента, листать, закрыть |
| `/approve UUID`, `/deny UUID` | Подготовить разрешение или отказ для request ID |
| `/confirm UUID` | Отправить подготовленное решение для того же request ID |
| `/recovery` | Показать причину восстановления и точные снимки действий с неизвестным исходом |
| `/ack UUID` | Подтвердить ознакомление с просмотренным исходом; исходный запрос не повторяется |
| `/help`, `/quit` | Справка и выход |

Текст продолжает выбранную завершённую, ошибочную или приостановленную задачу,
если нет ожидающего подтверждения. Для остальных состояний используйте `/new`.
История выбранной задачи проверяется раз в две секунды: это polling, а не
поток токенов. EOF и `/quit` завершают CLI; Ctrl+C завершает процесс обычным
сигналом. Выход **не отменяет** задачу backend — для отмены есть `/cancel`.

## Подтверждение инструментов

CLI показывает неизменяемый снимок: task/request/execution ID, tool-call ID,
инструмент, сервер и точные аргументы. Разрешение доступно только после вывода
всех страниц через `/more`, затем нужны `/approve UUID` и `/confirm UUID`.
Отказ также требует точного UUID и отдельного подтверждения. Enter не одобряет.

Оба потока, stdin и stdout, должны быть терминалами; через pipe решения
запрещены. Смена выбранной задачи не меняет открытый снимок. Изменённые,
отменённые и повторные запросы блокируются. Перед POST клиент заново проверяет
полное равенство снимка; окончательная атомарная проверка остаётся в backend.
Диалог больше 64 КиБ нельзя ни разрешить, ни отклонить этим CLI; задача может
быть отменена. Управляющие символы и Bidi в ответах раскрываются как текст.

## Проверки

```bash
cargo test --locked
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
python3 tests/cli_pty.py target/debug/kaic-cli
```

PTY-проверке нужен уже собранный бинарник (при `CARGO_TARGET_DIR` путь другой).
Тесты используют локальные HTTP-дубли; модели, внешние провайдеры и настоящий
токен не нужны. Среда должна разрешать loopback TCP bind и создание PTY.

## Границы реализации

Это построчный CLI с обычным терминальным вводом, без raw mode, полноэкранного
layout и встроенного редактора. Фоновый вывод может пересекаться с набираемой
строкой. UI-framework не добавлен; Ratatui/Crossterm требуют отдельного решения.
Канонический `Kich.png` не заменяется ASCII-приближением и здесь не отображается.

Сессия — представление сохранённой задачи backend; отдельного session API нет.
Skills, субагенты, diff/workspace, поток токенов, token usage и стоимость через
текущий API недоступны. SQLite-история не восстанавливает работающий исполнитель
после аварии: backend переводит прерванные задачи в состояние восстановления.
`/models` показывает загрузку, а не проверку доступности провайдера.
CLI не читает workspace и не исполняет shell/MCP/инструменты самостоятельно.

## Восстановление после сбоя

`--tasks`, `--show UUID` и `/history` показывают причину восстановления.
Чтобы проверить неизвестный исход, выполните `/use UUID_ЗАДАЧИ`, затем
`/recovery`: CLI выведет исходные task/request/execution ID, сервер, инструмент
и точные аргументы. Проверьте результат во внешнем инструменте самостоятельно.
Затем `/ack UUID_ЗАПРОСА` сохраняет ознакомление. Требуются интерактивные stdin
и stdout; перед POST клиент обновляет полный снимок, а backend атомарно
проверяет решение. При конфликте или сетевой ошибке заново откройте `/recovery`.

Ознакомление не означает разрешение и не повторяет исходный запрос. Backend
сохраняет его историю. Для намеренной новой попытки нужно отдельное продолжение
задачи и новый запрос с новым UUID. Пока остались неизвестные исходы, CLI
блокирует продолжение даже при статусе «пауза». С backend предыдущей версии
отсутствующие поля восстановления читаются как пустые.

Собственная реализация KAIC не заимствует исходники OpenCode/OpenTUI или Claude
Code. `publish = false` сохранён. Лицензионные ограничения распространения —
в [предыдущем отчёте](../docs/research/implementation-status.md).
Текущий этап и файлы: [CLI-first](../docs/cli-first.md).
